# Organización del trabajo

## Enfoque

Trabajo en iteraciones cortas (estilo Agile), con tareas pequeñas y visibles en un tablero.

## Flujo propuesto

- **Backlog**: ideas, features y bugs sin priorizar.
- **Ready**: tareas definidas (criterio de aceptación claro y tamaño chico).
- **In progress**: máximo 1–2 tareas en paralelo.
- **Review/QA**: verificación rápida (manual) y revisión de cambios.
- **Done**: cerrado.

## Cómo creo tareas

- **Historias/Features**: enfocadas en valor de usuario (ej. “Registrar un gasto”).
- **Tareas técnicas**: soporte (ej. “Crear tipos y helpers de fechas”).
- **Bugs**: reproducible + esperado vs actual.

## Definición de “Done”

- Código compila y corre localmente.
- UI mínima y usable para la funcionalidad.
- Estructura de carpetas mantenida (components/pages/hooks/types/utils/context/api).
- README actualizado cuando impacta el uso o setup.
